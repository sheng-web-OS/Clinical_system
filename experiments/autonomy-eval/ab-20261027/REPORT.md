# 隔離 Agent 對照：共同品質提示 vs 加載完整自治 SOP

日期：2026-10-27（Asia/Taipei）。狀態：**探索性開發 Pilot；未證實系統能力增益。**

## 結論

本輪**沒有觀察到額外辨錯或修正方案收益**。共同品質提示組與加載完整 SOP 組都完成 72/72 正確分類，36/36 缺陷定位、72/72 修正／保留方案通過分離 AI 評閱；24 個案例都在三次重複中通過。

這是小型有限輸入的提示條件比較，不能宣稱兩套系統等效，也不能用它證明無人督導營運、真實文章修復、真人學習效果或節省使用者時間。題集有明顯提示與天花板效應，**不據此提高成熟度**。

## 方法與固定條件

- 在工作者啟動前，以 commit `8e35b59e2bb26d00a7191ccb6f715f73977126f3` 保存 protocol.json 與任務封包 SHA-256。
- 被評估規則來源：PR #155 commit `141958a3eca91995d6fa9fd7048a85e2035c37f4`。Baseline 是共同品質提示，不是整套舊 Clinical OS 的完整 Runtime；另一組額外收到同一版完整自治 SOP。其餘輸入與輸出欄位、限制相同。
- 20 個既有可見開發案例加 4 個新合成較長情境；每組 3 個 fresh-context batch，每批 24 題：共 6 個工作者、144 份案例回覆。四個新情境不稱外部 holdout。
- 每組同一繼承模型與 effort 設定、未作 model override；工具未回傳可核對的精確模型版號、採樣種子及 token cap。只能聲明相同繼承設定及輸出限制，不能聲稱完全控制底層採樣或實際 token 預算。
- 每個 replicate 的兩組案例順序相同，以固定 shuffle 交錯次序。D/N 標籤、預期行為、原事件來源與配對答案未交給工作者。N10 的懸空「上述文字」在兩組都展開為同一段自足敘述，未修改原始來源題集。
- 六個工作者皆 fork_turns=none，只准讀各自 task JSON、不查網路／原庫／其他輸出；工具層仍共享檔案系統，因此這是指令式隔離，不是權限沙箱認證。
- 原始輸出保存指紋後，隨機換成匿名 record_id、移除組別與 trial，交給第七個 fresh-context AI 判讀原始定位、方案充分性與新引入重大錯誤。144 份全數審完，無參考標籤爭議。隱去明示組別不保證語氣完全無法洩漏條件；不是專科醫師審稿，也沒有第二名評閱者一致性測試。
- 六次工作者皆一次成稿，沒有挑成功重跑；試跑輸出與分離評閱屬真實 Agent 執行，與先前純資料完整性單元測試分開。

## 結果

| 項目 | 共同品質提示 | 加載完整 SOP |
|---|---:|---:|
| 獨特案例 | 24 | 24 |
| 案例回覆（24 × 3） | 72 | 72 |
| 分類符合題設 | 72/72 | 72/72 |
| 缺陷定位正確 | 36/36 | 36/36 |
| 正常案例誤擋 | 0/36 | 0/36 |
| 修正／保留方案通過 AI 評閱 | 72/72 | 72/72 |
| 三次皆通過的案例 | 24/24 | 24/24 |
| 回覆新引入重大問題 | 0 | 0 |
| 任務 JSON 字元總量 | 11,376 | 48,756 |
| 回覆 location/reason/correction 字元總量 | 5,893 | 6,086 |

任務 JSON 字元量為 **4.29 倍**，回覆欄位字元量為 **1.033 倍**。這只量到指定封包與回覆字串，不含共同系統／工具上下文；不是 API token、金額、推論時間或人工成本。未知的人工分鐘與中斷次數在 actual-run 與摘要中維持 null / NOT_MEASURED。

144 份回覆不是 144 個獨立病例；實際只有 24 個獨特案例與 6 個工作者上下文，每批案例共享同一上下文。未作顯著性或等效推論；零觀察重大錯誤不能證明罕見風險受控。

## 測試本身的品質缺口

多數種子直接描述缺陷，例如「未說明變數」、「審核紀錄卻聲稱已查圖」，很容易從題設辨認答案。未給額外答案／位置提示，不等於案例文字完全未提示問題。它們適合檢查基本契約，**不足以測試使用者真正需要的『從未被點出問題的原始文章自行辨錯』**。四個較長情境也沒有打破天花板。

因此各摘要中歷史欄名 autonomous_discovery 在本輪只能解讀為「對開發題設缺陷的識別」，不能當營運上的自主發現率。欄位一律保留 DEVELOPMENT_ONLY、autonomy_validated=false、learning_effect_validated=false、release_approval=false。

## 依結果採用的規則

1. **不預設全文注入 SOP**：保留契約作治理來源；任務預設只取共同品質契約與相關失敗／規則片段。這與既有 Lite／按需調用原則一致。本輪不支持每次全文載入，但不能據此刪除安全或證據契約。
2. **測試難度也要驗收**：正式自主辨錯驗收須用未被問題描述預先標示的原始完整段落、相鄰轉折與必要來源包；正常／缺陷對照須匹配長度、語氣與格式。先由分離審稿脈絡確認存在真實可定位差異，不能在題幹直接把差異說出來。
3. **天花板時不升級能力**：兩組皆高分且無差異時標「無可觀察增益／辨識力不足」，不宣稱等效、勝出、減少維護或自我改善。
4. **保留真正有證據的工程防線**：之前重複 trial／假獨立資料的反例修復，有獨立的程式前後證據；不把它與本輪零語義增益混成一個總分。
5. **下一層驗證**：以原始長文、跨段隱性前提、證據更新後的漏修與實際中斷接續作較難 Pilot，固定來源與預算再比較。真人學習與使用者實際介入時間繼續分開量測；本輪不填補。

## 可重現產物

- protocol.json、preregistration-sha256.json：事前固定條件與六個任務封包指紋。
- *-task.json、*-responses.json：六次指定輸入與原始輸出。
- execution-ledger.json：實際工作者脈絡及輸出指紋；檔案時間不作模型延遲對照。
- gold-and-mapping.json、blinding-key.json：對照答案、匿名 ID 還原鍵；工作者不得讀，試跑結束後才隨成果保存。
- blinded-review-packets.json、blinded-grades.json：匿名交付及分離評閱。
- evaluation-suite.json、*-actual-run.json、*-summary.json：既有工具可重算的真實 Agent 紀錄；repair 指標限於修正提案，未實際改文章。
- comparison-summary.json：逐組數據與結論邊界。
- analyze_ab_evaluation.py：重算腳本，以 --data-dir 指定本目錄、--repo-root 指定儲存庫根目錄，使用既有工具與原始結果重建彙整。

這些資產只留私人庫，不加入 site/pages.json，亦不代表合併、正式部署或作者醫學核准。
