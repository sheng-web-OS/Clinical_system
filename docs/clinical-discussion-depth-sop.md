# Clinical Discussion Depth SOP｜臨床論證深度與事前口試閘門

**適用範圍**：Clinical_system／謝小生製作的 CBD、case discussion、正式醫學報告中的 Discussion，以及以臨床決策為核心的深度教材。此 SOP 是既有 [EPQC](editorial-prose-quality-contract.md) 與 [semantic release gate](editorial-semantic-release-gate.md) 的**專用增補**，不是新評分平台。個案簡報和 Discussion 不得混同；當前一位報告者已呈現病歷，Discussion 不需重複完整 case presentation，但須引用決策必要的已知個案條件。

**失敗錨點**：[#203 神外 BA aneurysm CBD 教學失敗](https://github.com/sheng-web-OS/Clinical_system/issues/203)；治理總帳 [#133](https://github.com/sheng-web-OS/Clinical_system/issues/133)。2026-09 原九頁 Discussion 被現場主治醫師評為整體臨床論證非常不深入；2026-10 事後 AI 讀稿仍先自評 78/100，顯示生成與審稿共用的「架構漂亮＝深度足夠」假陰性。使用者提供的是口頭回饋，**並非可假設存在的正式教師評分單**。

## 0. 不可替代的品質原則

- Discussion 的目的不是覆蓋最多主題，而是回答**對診斷、治療或風險判斷最有影響的臨床矛盾**。頁數、名詞、漂亮架構、引用量、指南等級、AI 自評都不得補償缺乏論證。
- **臨床邏輯**先建立合理的可能性／選項，依可取得的病人事實找出關鍵區辨訊息；**EBM**再用原始研究與指南校準效益、傷害、可信度和適用性。機轉合理不等於臨床效益已獲證明；引用指南亦不等於完成推理。
- 核心命題必須可受質疑：**如果關鍵條件改變，何時應改判？什麼仍然未知？** 無法回答者標「未解」，不得寫成確定結論。
- 不得用 AI 想像填補真實病例缺口、事後推定主治醫師決策理由、以文獻中的另一位病人冒充本案；病例缺值可明示「無法據此確認」，必要時縮小題目或降級成「general overview」。
- 出版／交付前需要**與撰稿脈絡分離的獨立審查**。同一輪寫作者自我反省不等於獨立檢驗；獨立 AI 審稿也不等同具執照專科醫師同儕評核。

## 1. 先選問題，再決定深度與篇幅（Question Triage）

**輸入**：報告用途／對象、已知病例摘要與原始證據、可用時間、團隊指定的報告邊界。若僅分派 Discussion，主動辨識前一段病例報告已涵蓋事項，不再假裝自己要完整報告病程。

1. 由患者的決策轉折列出候選問題，不直接把 guideline 章節、術式目錄或併發症清單當作 Discussion 大綱。
2. 每個候選問題內部寫明：「**哪兩種合理選項或機轉在競爭？**」「**何時會改變臨床行動？**」「**哪項病人證據或研究最能區辨？**」；若答不出，先研究問題本身而非設計投影片。
3. 優先選 **1–2 個高臨床影響／高不確定性／可被證據有效處理**的主題。必要的背景可用一兩句建立，但不能因為要湊成三問、九頁或一個固定模板而分散深度。
4. 先寫**主命題與最強反論點**。例如：「當 ruptured aneurysm 與急性 symptomatic hydrocephalus 並存，先 EVD 還是先 securing？」「我認為 X；但 Y 條件一改就可能不成立」。若沒有真正會讓判斷分岔的條件，需重新選題。

**Gate Q（必過）**：每個保留的核心問題，都能指出它的決策後果、至少一個真正合理的競爭解釋／選項、至少一項可能改判的資訊。純「What is…／Overview of…」不能標示為深入的臨床 Discussion。

## 2. 逐核心命題建立可辯護的論證（Claim → Mechanism → Discriminator → Decision）

針對每個**主要結論**，在私有研究筆記完成一條精簡的 **Decision Warrant**，不強迫在投影片逐欄呈現：

- **當時問題與資訊狀態**：臨床時間點、已確認的症狀、PE、影像、實際處置；當時沒有的資訊明確標出，避免後見之明。
- **競爭機轉／可行選項**：至少說出最強替代解釋或方案，以及各方案主要可預期效益、傷害、限制。不是把 differential 或 devices 僅列成清單；要交代為何彼此有競爭性。
- **能真正區辨的證據**：什麼病人發現、時間趨勢、檢查效度或研究結果會增加／降低某個選項的支持度？哪些陰性結果不能排除？
- **證據層級與可移植性**：生理推論、病例報告、觀察研究、比較研究、RCT、guideline、專家共識各自支持到哪裡；重要偏差、研究族群、比較組、結果指標／絕對效益及來源限制。不得用 guideline 的推薦結果倒推本案的實際動機。無適用 RCT 亦可合格，但須誠實說明可得證據的界限。
- **決策分岔／反事實**：指出至少一個會使結論改變的患者條件、解剖或風險，清楚說明 why。臨床資料不足以選邊時，呈現條件式結論，不硬湊唯一答案。
- **Back to our patient**：用本案已核實、真正影響論證的條件回扣；若本案影像／手術紀錄缺失，保留未知並提出需要確認的資料，不聲稱原團隊必然依此決策。

**Gate D（必過）**：每個主要臨床結論都不得僅靠「因為指南建議」「因為位置深」「要看病人情況」「治療後要追蹤」等正確但無區辨力的句子成立。若無 competing options、discriminating evidence 或 decision pivot，標示 **HOLD／非深入版**。

## 3. 原始證據核對（Evidence, not decoration）

1. 先查本案關鍵事實與實際臨床時序，再查現行原始指南的全文推薦條件；若結論涉及療效、併發症或兩方案比較，向上追到主要研究／系統性回顧及其研究限制，不能只用 guideline 引言或二手概述充當定量證據。
   - **讀研究先問問的是哪個 PICO**：比較的是誰（是否有 indication confounding／不同 procedure）、介入在什麼時間、結局是影像可見 abnormality 還是病人重要的 symptomatic event、追蹤時窗多長；『無顯著差異』不能直接翻譯為『等效／安全』。不要因為一篇研究有 OR/P 值便視為能決定本案選項。
   - **臨床體系也是可改判條件**：治療是否真的可近、跨院轉診與等候時間、醫療團隊能力能否影響安全處置的先後；如果這個情境被 guideline 特別規範，必須從原始 supportive text 取回，而不只讀 recommendation 表格。
2. 每項關鍵醫學主張記錄最低限度的「來源定位＋實際查核範圍＋哪些推論仍不成立」。涉及 Figure/Table 需核對原圖、標題、分組、軸、圖說、註腳與時間點；影像示例必須標示是**本案**或**不同文獻病例**。
3. 針對專業爭議，分開敘述：生理上可能發生什麼、研究實際顯示什麼、指南在什麼條件下推薦、對本案可否直接適用。若來源互相衝突，保留衝突並按品質與適用性分析，不用更響亮的語氣掩蓋。
4. 避免只為增加文獻密度或外觀專業而插圖。每張圖都要回答一項前文已提出的必要問題，圖像與讀者文本仍依既有 figure／出版契約驗收。

**Gate E（必過）**：重要比較主張能追到原始來源與適用條件；來源無法核對、把機轉當效益證明、混用不同個案或忽略決定性反證，均 **HOLD**。

## 4. 將研究轉譯成可聽懂的學術 Discussion

以「問題為何困難 → 必要的基礎解剖／生理／術式概念 → 競爭機轉與選項 → 什麼證據改變判斷 → 這位病人符合到哪一步／未知為何」形成**自然的連續敘事**；必要時可先展開一般醫學背景，最後明確回扣病人。這是認知順序而不是固定五頁模板。

講者不應把來源管理、私有問答表格、研究審計與 Agent metadata 直接貼在對外投影片。真實不確定性、研究限制及重大反例則必須保留。**時間不夠時減少議題數，不刪除支撐主要結論的必要中介。**

## 5. 獨立口試：在使用者上台前發現失敗

**審稿者的任務是找出最可能讓報告被專科主治醫師質疑的薄弱點，不是校稿或讚美。**

- 審稿者須取得完整稿、任務邊界、關鍵原始資料與來源；與作者的直接自評分開。優先**先獨立寫出值得討論的問題**，再讀作者所選主題，避免被既定投影片標題錨定。
- **防止答案洩漏**：審稿者第一輪只取得凍結原稿、任務與原始文獻；在提交且封存原始問答與裁決之前，不可讀作者的 RED audit、範例答案、修訂稿或預設分數；若已看過，必須標記 **CONTAMINATED_REVIEW**，僅可作非盲編輯，不得算獨立 RED 效力驗證。
- 對每個主要臨床決策至少提出三類非預告質疑：**Why**（機轉與最強競爭解釋）、**How do you know**（病人／研究證據能區分什麼）、**What if**（關鍵條件改變結論如何翻轉）。其中至少一次要求明分機轉與 EBM。
- 審稿者不只看答案是否提到名詞，而要指出「這一句在何種情境下為假」「缺什麼最關鍵的 evidence」「是否迴避真正較強的對手方案」。當作者給出條件式回答時，不能因缺少唯一答案而扣分；當作者用正確空話掩飾無法分辨時，必須退稿。
- 提供具體反例及需要修改的段落，再交回 writer 修正；改完的主要結論須重審，不能用先前票據沿用。
- 若工具或工作階段無法建立真正分離的審稿脈絡，寫 **INDEPENDENT_REVIEW_NOT_DONE／HOLD**，不得聲稱已完成專家級驗收。

**Gate R（必過）**：獨立審稿者須判斷核心選題、論證與反事實均足以承受實質追問；不能用數字、排版或 CI 通過補償任何核心缺陷。

## 6. 交付決策與最小追溯記錄

- **PASS（深度 Discussion 候選）**：Q、D、E、R 都有具體審查證據且未有醫學安全阻擋；只是可交付的編輯候選，不冒稱專科醫師評核或已正式發表。
- **REVISE／HOLD**：任一核心問題未建立競爭論證、來源衝突未解、審稿者無法回答實質追問、原病例適用性被誇大或缺少獨立審核，則暫不標「準備充分」；由既有 owner 改稿後重新驗證。
- **OVERVIEW_ONLY**：如用途明確只要概覽，可降級且標示定位與限制；**不能用降級偷渡原本要求的深入 CBD**。
- **NOT_VERIFIED**：未實際查核的來源、病例、口試、CI／部署一律寫未驗；不能以預計作業當已完成。不得默認使用者同意醫學高風險／公開發布。
- 最小審查 receipt：稿件名稱／Git blob SHA、日期、選題與最強反論點、至少三個具體問答及失敗修訂點、關鍵證據核查邊界、writer/reviewer 身分與分離方法、Q/D/E/R 狀態、最終判定與 issue/PR 連結。**僅存既有私有 PR／issue 或既有 audit 管道**，不新增服務、儀表板或排程；改動稿件 SHA 即重審。審查語言不進讀者正文。

## 8. 責任界線與低維護實施

- 寫作者：選題、臨床論證、查證與修稿。
- 分離的 reviewer：挑戰主命題、比較競爭方案、提出反事實，明確裁決；不得預填 PASS。
- 現有唯一 editorial owner：保存最小證據、安排重審與更新 [#203](https://github.com/sheng-web-OS/Clinical_system/issues/203)／[#133](https://github.com/sheng-web-OS/Clinical_system/issues/133)，不另建併行追蹤主線。
- 使用者：不應替 AI 執行例行的深度檢查；只有無法排除的重大醫學歧義、真正需要臨床授權／正式發布的高風險事項再要求判斷。
- 原始神外旋轉與 intracranial aneurysm 材料屬**私有測試樣例**，依 AGENTS.md 不自動進小麻公開教材池。
