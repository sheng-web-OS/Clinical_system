## Policy agreed for the Clinical_system release cycle

- **Agent owns**: independent research and drafting; fact/claim extraction; direct citation verification; prevention of copying publisher pixels; corrections to original figures; source link validation; layout at 360/390/1280px; site and exam regressions; same-commit build; preparing a deploy-ready PR and checking actual deployment afterward. A CI pass is an **engineering result, not a medical result**.
- **Designated final reviewer: project owner (author self-review)**. The owner judges whether a P0 action instruction is safe, a P1 diagnostic inference/numeric boundary is supportable, and decisive figures could teach an unsafe shortcut. Present the exact excerpts, source locators, and full image/reader link; do not require the owner to repeat Agent's research. Because this is an **author/owner review**, do not label it external, blinded, independent peer review, or specialist certification. External review may be requested when the owner decides the residual risk warrants it, but it is not the default gate.
- **Release owner (same project owner)** records **ARTICLE ACCEPT / REQUEST CHANGES / HOLD** separately for each manuscript and decisive figure, with reviewed content SHA. Choosing the reviewer does **not** mean any article is approved. Article-specific approval is evidence for a release decision, not authorization for unrelated pages. Never merge a four-article Draft merely because one is accepted.
- **Author provenance**: Facebook canonical verification is not a gate for a new explicitly AI-integrated article; never label historical originals canonical without evidence. Pocket textbook **viewer PDF** page labels are allowed when explicitly labelled; do not invent printed page identifiers.
- **Rights**: the new decision figures and explicitly cited numerical case reconstruction contain no reproduced Pocket Medicine pixels; a subsequent addition of a third-party original image reopens rights review **for that image only**. Do not make general image clearance a perpetual blocker for pages using independent diagrams.
- **Change invalidation**: owner clinical sign-off applies to an individual article's Git blob SHA, decisive figure ID(s) and checked sources. Altering a signed high-risk clinical claim or decisive figure requires targeted re-review. Cosmetic/safe build changes need regression tests but should not invalidate unrelated medical signatures. Store the article blob SHA and separate deployment commit.
- **Sequential publication**: after the project owner affirmatively accepts a specific article's P0/P1 claims **and key figures**, and fresh release-commit CI succeeds, select only that article and the shared source page for a small release PR. The owner also explicitly authorizes merging/deployment; then Agent checks merged main, deploy status, live URL and mobile figures. Other manuscripts stay Draft/HOLD. Avoid additional parallel release infrastructure.
